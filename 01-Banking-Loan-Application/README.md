# Banking Loan Application Improvement

## Project Overview

This fictional business analysis case study examines a traditional bank loan application process and proposes improvements to make it more efficient, transparent, and consistent.

## Business Problem

A hypothetical bank relies on manual checks and communication between teams to review loan applications. This may contribute to incomplete submissions, processing delays, limited application status visibility, and inconsistent record keeping.

These are assumed problems for the case study and would need validation with stakeholders in a real engagement.

## Project Objectives

- Identify potential bottlenecks in the existing process.
- Document business and functional requirements.
- Define stakeholder needs and responsibilities.
- Propose an improved future-state process.
- Develop user stories and acceptance criteria.
- Prepare UAT scenarios and a requirements traceability matrix.

## Deliverables

1. Problem Statement
2. Stakeholder Analysis
3. Business Requirements
4. Functional Requirements
5. AS-IS Process Analysis
6. TO-BE Process Diagram
7. User Stories
8. Acceptance Criteria
9. Use Cases
10. Business Rules
11. UAT Test Scenarios
12. Requirements Traceability Matrix

## Approach

The case study follows a structured business analysis approach: define the problem, identify stakeholders, document requirements, model the proposed process, and connect requirements to validation scenarios.

## Tools

Microsoft Excel, diagrams.net (Draw.io), GitHub, and documentation tools.

## Status

Case study in development. Proposed requirements and process changes are illustrative and have not been validated against a real banking system.
